# Ранжирование русскоязычных поисковых фрагментов

**Результат v47 — 0.968667 Public NDCG@10.** Для каждого запроса требовалось упорядочить заданные фрагменты по релевантности. Первые версии оценивали каждый фрагмент отдельно. Наибольший прирост на заключительном этапе дала модель Jina, которая видит кандидатов вместе. Два следующих эксперимента показали, сколько текста ей стоит показывать и насколько результат зависит от порядка кандидатов. Финальная модель и её препроцессинг собраны в [solution.ipynb](solution.ipynb).

## Данные и схема проверки

Обучающая выборка содержит 31 530 пар «запрос — фрагмент» для 3 042 запросов, тестовая — 13 507 пар для 1 305 запросов. После удаления пробелов по краям пустыми оставались 1 382 заголовка в train и 691 в test. При обработке заголовков учитывались также текстовые заглушки. Для метаданных фрагмента отдельно отмечались ошибки разбора и недопустимые значения, например отрицательная длина статьи. Эти признаки использовались в лексической модели вместе с BM25 и TF-IDF.

Один фрагмент может встречаться у нескольких запросов. В пробном разбиении по запросам с 20% данных на валидацию 1 063 документа оказались одновременно в обучении и валидации. Поэтому пять фолдов формировались по связным компонентам графа «запрос — документ». Так все появления одного запроса и одного документа попадали в один фолд. Для обучения ансамбля использовались оценки базовых моделей на отложенных фолдах.

Метрика — среднее NDCG@10 по запросам. При сравнении вариантов у каждого запроса сохранялся исходный набор кандидатов. В таблице приведены результаты на 392 запросах Public Leaderboard. Локальные сравнения приведены отдельно.

**Как получили базовую модель.** Вначале проверялось, поможет ли BGE обучение на парах релевантных и нерелевантных фрагментов одного запроса. На пяти отложенных фолдах бинарная кросс-энтропия дала 0.937294 NDCG@10, парная функция потерь — 0.930785. В дальнейших версиях для BGE сохранили бинарную функцию потерь. Добавление дообученных Qwen 4B и 8B позволило поднять Public до 0.948356. Парная линейная модель, CatBoost YetiRank и дополнительное сравнение двух лидеров довели результат до 0.951970 в v35.

**Какие сигналы оказались слабее.** В v24 к ансамблю v17 добавили BGE-M3 MaxSim, который оценивает совпадения на уровне токенов. На тех же отложенных запросах NDCG@10 изменился с 0.955015 до 0.954921. В v30 проверили компактный bi-encoder с RankNet, InfoNCE и LambdaRank. На контрольном фолде лучшая из трёх смесей дала 0.952258 при 0.952621 у базовой модели. Обе проверки оставили прежний ансамбль основой для следующих опытов.

**Сколько текста нужно Jina.** В v44 совместная оценка фрагментов одного запроса подняла Public до 0.958216. В v45 на том же чекпоинте сравнили лимиты 256, 384 и 512 токенов на фрагмент при инференсе. На отдельном фолде для выбора настройки выиграли 512 токенов. На контрольных 609 запросах этот вариант исправил семь первых мест и испортил четыре относительно v44. Public вырос до 0.967034. Обучение с длиной 512 в v46 дало 0.965440, поэтому для следующего опыта сохранили чекпоинт v45.

**Насколько важен порядок фрагментов.** В v47 зафиксировали чекпоинт, длину 512 и долю Jina 0.75. Единственным изменением относительно v45 стало усреднение четырёх порядков подачи кандидатов вместо двух. На тех же 609 контрольных запросах NDCG@10 вырос с 0.970128 до 0.971345. У 27 запросов метрика улучшилась, у 13 ухудшилась, у 569 осталась прежней. В трёх запросах релевантный фрагмент вышел на первое место, в двух — уступил его нерелевантному. Этот фолд использовался в нескольких экспериментах. 95%-й бутстреп-интервал прироста по компонентам составил [−0.000962, 0.003541]. Доля Jina 0.80 дала выигрыш на контрольном фолде и проигрыш на фолде выбора настройки, поэтому в финале сохранили 0.75.

## Итоговая модель

Базовый ранг v35 объединяет оценки BGE, Qwen и лексического LightGBM. Отдельно Jina, дообученная с LoRA на конкурсных метках, оценивает список в двух перестановках и их обратных порядках. Четыре оценки каждого фрагмента сопоставляются по ID и усредняются. Итоговая формула — `0.75 × z(Jina) + 0.25 × z(−rank_v35)`, где `z` — стандартизация внутри запроса. При равных оценках первым идёт меньший строковый `id`.

Для дообучения используются метки из `train.csv`. Ноутбук загружает закреплённые ревизии начальных весов. Модель Jina распространяется по лицензии CC BY-NC 4.0.
